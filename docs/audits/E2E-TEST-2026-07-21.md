**1c. Auto-přepnutí brief → 'reviewed': FAIL — BUG NENAJDEN**

> **BUG-TEST1-001 — KRITICKÉ**  
> `weekly_briefs.status` se NIKDY nepřepne na `'reviewed'`.

>
> **Fix (10 min):** Po každém PATCH decision zkontrolovat, jestli v `brief_id`
> zbývá nějaký řádek s `admin_choice IS NULL`. Pokud ne → 
> `UPDATE weekly_briefs SET status='reviewed', reviewed_at=now()`.
> ```typescript

## TEST 3 — Learning Memory pattern detection

### Co bylo testováno
Statická analýza `lib/learning-memory.ts` + migrace `20260714_learning_memory.sql`

### Výsledky

**3a. Práh 3 výskyty → shouldCreateLearning: PASS (logika správná)**
```typescript
// observePattern() — řádky 139–159
if (existing) {
  const newCount = existing.occurrences + 1
  // UPDATE occurrences = newCount, last_seen = now(), example_contexts = exampleContext
  return { occurrences: newCount, shouldCreateLearning: newCount >= 3 }  // ✓
}
// INSERT occurrences = 1
return { occurrences: 1, shouldCreateLearning: false }  // ✓
```

**3b. example_contexts neuchovává historii: PARTIAL — DATA LOSS**
> **BUG-TEST3-001 — střední**  
> `example_contexts` je JSONB pole v DB (ne pole/array).  
> `observePattern()` PŘEPÍŠE `example_contexts` při každém volání:  
> ```typescript
> .update({ example_contexts: exampleContext })  // Přepis, ne append!
> ```
> Po 3 voláních `example_contexts` obsahuje POUZE kontext z 3. volání.  
> Uživatelský test "example_contexts obsahuje 3 záznamy" by SELHAL.  
>
> **Dopad:** Při manuální analýze patternů je k dispozici jen poslední kontext,
> ne celá historie. Tím se zhoršuje schopnost rozpoznat common pattern.  
>
> **Fix:** Buď (A) uložit jako pole JSON a appendovat:
> ```typescript
> // Fetchnout existing contexts, appendovat nový:
> const prev = existing.example_contexts ?? []
> const updated = Array.isArray(prev) ? [...prev.slice(-4), exampleContext] : [exampleContext]
> .update({ example_contexts: updated })
> ```
> Nebo (B) akceptovat jako is — pro detekci prahu (≥3) to nevadí.

**3c. API signature: PASS**
```typescript
// Správné volání (objekt, ne positional args):
await observePattern({ signature: 'test_x', description: 'Test', exampleContext: {ctx: 1} })
// Vrací: { occurrences: number, shouldCreateLearning: boolean }
// (ne shouldPromote — to je jiný název z task descripce)
```

**3d. Test nemohl být proveden live** — vyžaduje DB přístup.

**SQL pro manuální test:**
```sql
-- Setup
INSERT INTO patterns_observed (signature, description, occurrences, status)
VALUES ('test_e2e_pattern', 'Testovací pattern', 0, 'open')
ON CONFLICT (signature) DO NOTHING;

-- Simuluj 3 volání:
UPDATE patterns_observed SET occurrences = occurrences + 1, last_seen = now()
WHERE signature = 'test_e2e_pattern';
-- (spusť 3×)

-- Ověř:

FROM patterns_observed WHERE signature = 'test_e2e_pattern';
-- Očekáváno: occurrences=3, should_create_learning=true

-- Cleanup:
```

## TEST 5 — Rollback capability

### Co bylo testováno
Analýza `executor_operations` schématu + data z 125 operací (21.7.)

### Výsledky

**5a. Data pro rollback dostupná: PASS**
```sql
SELECT operation_type, target_slug, field_changed, value_before, value_after
FROM executor_operations WHERE status='applied' LIMIT 5;
```
Schéma `executor_operations` má `value_before TEXT` a `value_after TEXT`.  
Pro `fix_affiliate_url` operace: `value_before = NULL` (affiliate_url bylo prázdné).  
Pro `recalc_score` operace: `value_before = 'null'` (score bylo NULL).

**5b. Rollback affiliate URL = SET NULL: PASS**
```sql
-- Rollback jedné operace:
UPDATE product_offers
SET affiliate_url = NULL
WHERE id = (
  SELECT target_id::uuid FROM executor_operations WHERE id = '<operation_id>'
);
-- Nebo batch rollback (vše z 21.7.):
UPDATE product_offers po
SET affiliate_url = NULL
FROM executor_operations eo
WHERE eo.target_id = po.id
  AND eo.operation_type = 'fix_affiliate_url'
  AND eo.status = 'applied'
  AND eo.created_at::date = '2026-07-21';
```

**5c. Navrhovaná struktura rollback skriptu:**

```typescript
// scripts/executor-rollback.ts
// Usage: npx tsx scripts/executor-rollback.ts --since="2026-07-21 08:00"
//         npx tsx scripts/executor-rollback.ts --operation-id=<uuid>

// Bezpečnostní omezení:
// - Pouze operace mladší než 7 dní
// - Dry-run jako výchozí (--execute pro skutečný rollback)
// - Log každého reverted op do executor_operations s status='rollback'

async function rollback(opts: { since?: string; operationId?: string; dryRun?: boolean }) {
  const cutoff = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000)
  
  // 1. Načti operace k rollbacku
  const ops = await supabaseAdmin.from('executor_operations')
    .select('id, operation_type, target_id, target_type, field_changed, value_before')
    .eq('status', 'applied')
    .gte('created_at', opts.since ?? cutoff.toISOString())
    .order('created_at', { ascending: false })  // Nejnovější první (LIFO)
  
  for (const op of ops.data ?? []) {
    if (op.operation_type === 'fix_affiliate_url') {
      // SET affiliate_url = NULL (value_before je vždy NULL pro tento typ)
      if (!opts.dryRun) {
        await supabaseAdmin.from('product_offers')
          .update({ affiliate_url: null })
          .eq('id', op.target_id)
      }
      console.log(`[rollback] ${opts.dryRun ? 'DRY' : 'APPLIED'}: ${op.target_type}/${op.target_id} affiliate_url → NULL`)
    }
    
    if (op.operation_type === 'recalc_score') {
      if (!opts.dryRun) {
        await supabaseAdmin.from('products')
          .update({ olivator_score: null, score_breakdown: null })
          .eq('id', op.target_id)
      }
      console.log(`[rollback] ${opts.dryRun ? 'DRY' : 'APPLIED'}: product/${op.target_id} score → NULL`)
    }
  }
}
```

**Priorita implementace:** Nízká — rollback affiliate URLs je triviální SQL (viz výše),  
není nutný skript pro autonomní operaci. Přidat až v okamžiku prvního bezpečnostního incidentu.
